# Rightnest 0.1.0 — Early Access

Right-side window controls for macOS. **Apple Silicon only.** Safari and Chrome are the primary targets; other applications are experimental or have limited coverage. Original macOS controls remain available.

## Download and install

1. Under **Assets**, download **Rightnest-0.1.0-arm64.dmg**. The `.sha256` file is an optional integrity checksum.
2. Open the DMG and drag **Rightnest** onto **Applications**, then eject the image.
3. Open the installed app. Try its test window, set up Window Control permission in macOS Privacy & Security, and return.
4. Turn on **Automatically place controls in other apps**, then choose **Continue in menu bar**.

[Installation, update and removal](https://github.com/Bartu-Ercan/Rightnest/blob/v0.1.0/docs/INSTALL.md) · [Türkçe kurulum](https://github.com/Bartu-Ercan/Rightnest/blob/v0.1.0/docs/INSTALL.tr.md)

**Signing:** locally signed, not Apple Developer ID signed or notarized. macOS may block downloaded copies; managed Macs may prohibit them. If macOS offers an explicit per-app Open Anyway option, review the source and limitations before using it. Do not disable Gatekeeper or remove quarantine through Terminal.

## In this release

- Minimize, fit/restore and close on the right, with yellow/green/red hover feedback.
- A fixed native-strip anchor during temporary coverage: hide while covered, then reappear in the same position and size. No sliding left or narrowing for a covering system indicator.
- Menu-bar controls, pause, per-app exclusions, English/Turkish UI and optional launch at login.
- A custom Retina drag-to-Applications installer with only two visible items.
- No account, backend, telemetry, screenshots or screen-recording permission. [Privacy](https://github.com/Bartu-Ercan/Rightnest/blob/v0.1.0/docs/PRIVACY.md).

## Validation and known limits

23 XCTest cases,100 standalone checks and28 native AppKit checks passed for the fixed-corner change. Release bundle and mounted installer checks cover signature,arm64 architecture,license,layout and absence of developer test entrypoints. Source CI is linked on the repository.

Safari and Chrome completed30-minute disposable-window sessions and all window actions before the final fixed-corner refinement. That refinement has automated state coverage; its new physical system-indicator behavior has not yet been independently reconfirmed. Do not interpret the older sessions as a new-policy30-minute pass.

- API minimum macOS13; tested device environment Apple M2/macOS27.0(26A428). Older macOS versions are not device-validated; Intel is not supported.
- Uncertain or occupied titlebars can hide controls. An outside shelf is used only when empty desktop space is verified; crowded Finder layouts can have no safe position. App eligibility is not compatibility proof.
- Full-screen windows,modal dialogs and open/save sheets are excluded. Discord and System Settings have no current complete action-test pass.
- Clean-user/browser-quarantine/update and broader display/one-hour testing remain incomplete. This is early access, not a broad stable-compatibility claim.
